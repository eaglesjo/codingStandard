# 共通 AI Agent ルール

これらのルールは、サポート対象のすべてのプロジェクトドメインに適用されます。

1. コードを変更する前に、実際のリポジトリ、ランタイム、依存関係、テスト、セキュリティ制約を確認する。
2. リソースに依存する設定を選ぶ前に、実際の実行環境を検出・計測する。
3. 特定のマシン、OS、CPU、RAM、GPU、アクセラレータ、IDEをプロジェクトの必須条件としてハードコードしない。
4. 再利用可能なドメインロジックはモジュールに置き、Notebookやスクリプトはオーケストレーションに集中させる。
5. 明示的な設定、再現性メタデータ、決定論的なパスを使用する。
6. シークレットをソース管理の外に保持する。
7. まず最小限の意味のあるテストで変更を検証し、その後に広範なテストスイートを実行する。
8. 環境検証後、マルチプラットフォーム対応が意図されていない限り、未使用の実行分岐や古いコードを削除する。
9. 長時間実行するワークロードでは、意味がある場合は検証、Early Stopping、最良 Checkpoint、Resume を使用する。
10. 実験では baseline、制御された variant、seed、metric、resource tracking を定義する。

## 標準実行ライフサイクル

```text
Discover → Detect → Measure → Resolve → Smoke Test → Lock → Implement → Validate → Record
```
